Publish the HTML edition

1Open it on your computer

  1. Download Md-Tanvir-Ahmmed-HTML-Edition.zip and extract it.
  2. Open the website folder.
  3. Double-click index.html. If it opens in a text editor, right-click → Open with → Chrome, Edge, Firefox or Safari.
  4. Try the navigation, Publications filters, Search and Download CV. JavaScript must be enabled.

You can also open the separately supplied Md-Tanvir-Ahmmed.html directly. It is the same website. Fonts, photographs, styling, scripts and the PDF are embedded; no installation is needed.

2Upload it to Cloudflare Pages

  1. Sign in to your own Cloudflare account.
  2. Go to Workers & Pages → Create application → Get started → Drag and drop your files. Choose the Pages direct-upload flow if the dashboard offers several options.
  3. Enter a project name such as tanvir-ahmmed; availability determines the final address.
  4. Upload the extracted website folder. It must contain index.html at its top level. Do not upload the full Next.js project here.
  5. Select Deploy site. Open the pages.dev address Cloudflare gives you.

Cloudflare supports folder or ZIP uploads in this flow. If using a ZIP, zip the contents of website so index.html is at the ZIP root. Official direct-upload instructions.

3Check and share your address

Open the site on your phone. Confirm the menu, portrait, publication filters, email link and CV download. Keep the HTML file as your backup. When its content changes, upload a replacement through the same Pages project.

Admin editing requires the full website. Uploading this HTML file does not create /admin, a database, password recovery or an inquiry inbox. The contact button opens an email application; it does not submit a saved form.

Done: you have a shareable public HTML website.

Publish the full website with admin access

Use a laptop or desktop for these one-time setup steps. After setup, routine content editing happens in your browser.

1Prepare your accounts and project

  • Your original Md-Tanvir-Ahmmed-Website.zip, extracted to a folder you can find.
  • A GitHub account for the source code and GitHub Desktop installed.
  • A Supabase account for the database, login and uploaded files.
  • A Vercel account for running the application.
  • A Cloudflare account for the Turnstile spam-protection widget.
  • Node.js LTS installed — version 22 or newer. The installer includes npm.

The project folder is the folder containing package.json, README.md, app, public and supabase.

Hosting plan: Vercel Hobby is limited to personal, non-commercial use. For a website offering paid consulting, select a plan that permits commercial use. Check provider pricing and usage limits before activating paid services. Vercel Hobby terms.

2Run the local visual preview

Windows: open the project folder in File Explorer. Click its address bar, type cmd, then press Enter. Run these commands one line at a time:

node -v
npm -v
npm ci
copy .env.example .env.local
npm run dev

macOS / Linux: use Terminal in the project folder and replace the copy command with cp .env.example .env.local. In Windows PowerShell, use Copy-Item .env.example .env.local.

Open http://localhost:3000. Keep the terminal running. This is a preview on your computer; the admin panel and inquiry storage are not connected yet. Press Ctrl+C in the terminal to stop the preview before changing the settings below.

Checkpoint: the homepage opens locally with your name, photo and content.

Set up Supabase and your administrator

3Create the database

  1. In Supabase, create a new project. Give it a recognisable name and save the database password securely.
  2. Wait for the project to be ready, then open its SQL Editor.
  3. On your computer, open supabase/migrations/001_initial.sql in a text editor.
  4. Copy the complete SQL into a new query in Supabase and select Run. Run this initial migration once in the new project.
  5. Confirm the query succeeds. The migration creates the content tables, administrator allowlist, security policies and storage buckets.

Keep site-media and inquiry-attachments private. The application controls public media delivery and private inquiry attachments. Do not switch these buckets to public to fix a setup error.

4Add your keys and create the admin account

  1. Find the project URL and API keys in the Supabase Connect dialog or Settings → API Keys.
  2. Open .env.local on your computer. Fill in the values below. Keep the other lines from the example file.
  3. In Supabase Authentication → Users, create an email/password user for yourself. Use your actual administrator email and a unique password. If offered, mark this owner account as email-confirmed.
  4. Set ADMIN_EMAIL to that exact email. Disable public signups in Supabase Auth settings for this owner-only site.
NEXT_PUBLIC_SITE_URL=http://localhost:3000
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVER_SECRET_KEY
ADMIN_EMAIL=YOUR_ADMIN_EMAIL
CONTENT_PREVIEW=false

The modern publishable key starts with sb_publishable_; the server secret starts with sb_secret_. This project's server variable is named SUPABASE_SERVICE_ROLE_KEY: put the backend secret there. A legacy service-role key can also be used if that is what your project provides. Keep server secrets out of public content, GitHub and chat. Supabase key guidance.

5Load your content and test login

In the terminal, from the project folder, run:

npm run seed
npm run dev

The seed command authorises your existing account, loads the initial website content and uploads the bundled photographs and public CV. It does not create a password. Existing content is preserved when the command is run again.

Open http://localhost:3000/admin/login and sign in. You should reach /admin/dashboard. Review the dashboard's verification notes before publishing uncertain content. The live inquiry form will be ready after Turnstile is configured.

Checkpoint: you can sign in and see your editable content in the dashboard.

Save the source code in GitHub

6Publish a private repository

  1. Open GitHub Desktop and sign in to your own GitHub account.
  2. Choose File → Add local repository and select the extracted project folder.
  3. If Desktop says the folder is not a Git repository, use its create a repository here option. Ensure the resulting repository folder is the same folder that contains package.json. Preserve the supplied files and .gitignore.
  4. Review the Changes list. .env.local, node_modules, .next and backups must not be included. The supplied .gitignore excludes them. .env.example should be included because it contains placeholders.
  5. If changes are waiting to be committed, enter a summary such as Initial academic website and commit them.
  6. Select Publish repository, name it tanvir-academic-website, leave Keep this code private checked, and publish.

Official help: add a local repository and publish an existing project.

Open the repository on GitHub. Its top level should show package.json and the application folders. The ZIP file by itself is not a deployable repository.

Create the Vercel deployment

7Get your website address

  1. In Vercel, create a New Project, connect GitHub and import your private repository.
  2. Select the Next.js framework. The Root Directory must contain package.json.
  3. Use npm ci for installation and npm run build for the build. Keep Next.js's default output setting. Select a supported Node.js version of 22 or newer.
  4. For this initial preview deployment, add only the two environment variables below. Leave Supabase and Turnstile variables unset for this first deployment.
  5. Deploy, then copy the stable production vercel.app address shown in the project's Domains area. Use that address consistently in the next steps.
CONTENT_PREVIEW=true
NEXT_PUBLIC_SITE_URL=http://localhost:3000

This temporary deployment displays the bundled preview so you can obtain the hosting address. Its localhost setting must be replaced before launch, and it does not accept admin edits or inquiries. Vercel deployment instructions.

Checkpoint: you have the actual website address Vercel assigned. You have not finished connecting the live backend yet.

Enable inquiries and password recovery

8Create your Turnstile widget

  1. In Cloudflare, open Turnstile and add a widget for this website.
  2. Add your actual Vercel production hostname, without https:// or a path. Select the managed widget mode.
  3. Save its public site key and private secret key for the environment variables in the next step. You do not need to move your domain's DNS to Cloudflare to use Turnstile.

The application already renders and verifies Turnstile. You only need to supply the keys and correct hostname. Turnstile setup.

Generate a separate random value for RATE_LIMIT_SALT by running this command on your computer, then save its output securely:

node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"

9Configure password-recovery URLs and email

In Supabase Authentication → URL Configuration, set:

  • Site URL: your exact production origin, for example https://YOUR_ACTUAL_SITE.vercel.app.
  • Redirect URL: the same origin followed by /auth/callback.
  • For local testing, also allow http://localhost:3000/auth/callback.

Use your assigned address in place of the example. Supabase redirect configuration.

Configure a production SMTP email service in Supabase Auth using an email-sending account you control. Follow that provider's sender verification instructions. The default Supabase email service has restrictions and should not be relied on for production recovery. Supabase SMTP setup.

For this project's password reset flow, request the reset and open the emailed link in the same browser. The callback then opens the reset-password screen. This site stores contact inquiries in the dashboard; automatic new-inquiry notification emails are not enabled.

Connect the live backend and launch

10Set production environment variables

In Vercel Project → Settings → Environment Variables, add or update the following for Production. Use the same Supabase project you seeded locally.

Variable name — copy exactlyValue
NEXT_PUBLIC_SITE_URLYour actual https://…vercel.app origin; no path or trailing slash
NEXT_PUBLIC_SUPABASE_URLYour Supabase project URL
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEYSupabase publishable key
SUPABASE_SERVICE_ROLE_KEYSupabase backend secret; server only
NEXT_PUBLIC_TURNSTILE_SITE_KEYTurnstile public site key
TURNSTILE_SECRET_KEYTurnstile private secret; server only

ADMIN_EMAIL is used by the local seed script; it is not required by the running Vercel site. Enter values without placeholder text, extra quotes or spaces. Never rename a server-only secret with a NEXT_PUBLIC_ prefix.

11Redeploy

Save the variables. In Deployments, redeploy the production deployment. Environment changes apply to a new deployment; an already-running build does not receive them automatically. Vercel environment variables.

When the deployment is Ready, open the production address. Visit /admin/login, sign in and check the dashboard. Keep your local NEXT_PUBLIC_SITE_URL at http://localhost:3000 for local development; the hosted Vercel value must be the public HTTPS address.

Checkpoint: the live site reads your database and your authorised administrator can sign in.

Connect a custom domain later

  1. Register a domain you choose, or use one you already own.
  2. For the full website, open Vercel → Project → Settings → Domains and add it.
  3. At your domain provider, enter the exact DNS records Vercel displays. Wait for domain verification and HTTPS readiness. Vercel domain instructions.
  4. Choose one primary address, such as the bare domain or the www version, and use it consistently.
  5. Update Vercel's NEXT_PUBLIC_SITE_URL, Supabase's Site URL and /auth/callback redirect, and the Turnstile hostname.
  6. Redeploy and repeat the contact and password-reset checks on the new domain. Update any explicit canonical URLs previously entered in Admin → SEO Settings.

If you published only the HTML edition, use the Pages project's custom-domain settings instead. The full Next.js application's admin features still require its server and Supabase.

Back up the content and files

Use Admin → Backup / Export for JSON or CSV copies. Those exports contain content and media references; they do not include every uploaded file's bytes. For a content-and-files backup, run this from your local project with the correct server credentials in .env.local:

npm run backup

The command saves a dated folder under backups, including media and inquiry attachments. Store encrypted copies elsewhere. Keep Supabase database backups as well; authentication accounts require their own backup/recreation process. See the project's docs/BACKUP.md. Never publish backups, which may contain private messages.

Routine content edits stay in Supabase. For future application fixes or dependency updates, commit the reviewed code in GitHub Desktop and push it; Vercel can deploy the new version. Keep the original ZIP and this guide.

If something does not work

The HTML download opens as text or inside a file preview.

Save the file to your computer, then open it with a browser. Confirm the filename ends in .html, not .html.txt. Some document previews deliberately do not run JavaScript; use the actual browser file.

I uploaded the HTML but /admin does not exist.

That is expected for the HTML snapshot. Follow the full website steps using the original Next.js project ZIP to get an administrator dashboard.

The HTML hosting address shows a 404.

Check the upload's root contains index.html. Upload the website folder's contents, rather than a parent folder containing another website folder.

“npm is not recognised” or PowerShell blocks npm.ps1.

Install Node.js LTS, then reopen the terminal. On Windows, run the guide's commands in Command Prompt (cmd) instead of changing PowerShell security settings.

npm cannot find package.json.

You are in the wrong folder. Open the extracted project's inner folder containing package.json, then open the terminal there.

The SQL migration reports a table already exists.

Do not delete tables or rerun fragments blindly. Check whether the migration already completed. This initial schema is for a new Supabase project; preserve any existing data and inspect the exact error.

Seeding says the administrator was not found.

Create the email/password user in the same Supabase project's Authentication → Users first. Check that ADMIN_EMAIL matches exactly and both Supabase keys belong to that project.

Admin login fails or I am not authorised.

Check the email/password, confirm the account is enabled and email-confirmed, and ensure npm run seed completed for that email. A Supabase login alone does not grant admin access; the account must be in the allowlist. Restart locally or redeploy after changing keys.

The deployed site still says preview or content edits do not show.

Confirm Production has both Supabase client settings, the correct backend key and CONTENT_PREVIEW=false. Redeploy. Check the edited item is Published, Show on website is enabled, and the relevant homepage section is visible. Refresh the public page.

The contact form fails its security check.

Confirm the Turnstile widget allows the exact hostname you are visiting. Check the public site key and matching secret, the random salt, and that NEXT_PUBLIC_SITE_URL matches the production HTTPS origin. Redeploy after corrections. Test on the stable production domain.

Password-reset email does not arrive or the link fails.

Check spam, SMTP delivery logs and your verified sender configuration. Confirm Supabase allows the production /auth/callback URL. Request a fresh link and open it in the same browser where you requested the reset.

Vercel's build fails.

Read the first meaningful error in the build logs. Check the Root Directory, Node version, committed package-lock.json, and environment values. Run npm ci followed by npm run build locally to compare. Do not upload only the ZIP or select static HTML output for the full project.

A media upload is rejected.

Use a supported image or PDF. This project limits admin uploads to 4 MB after image optimisation and inquiry attachments to 3 MB. Compress an oversized PDF before trying again. Leave storage buckets private.

If you need help with a failed step, share the step number and the error text with secrets removed. Keep passwords, API secret keys and recovery links private.
